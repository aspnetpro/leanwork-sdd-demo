## Findings detalhados

### 🟢 Sugestões

Melhorias opcionais, ficam a critério do autor.

#### R-01 — Allowlist de esquema sem comentário apontando a natureza crítica da checagem

- **Eixo:** 5. Qualidade do código
- **Referência cruzada:** ADR-005
- **Evidência:** `src/Encurtador.Web/Servicos/ValidadorDeUrl.cs:18-21`
- **Descrição:** O próprio texto da tarefa no plano chama a checagem de esquema de "o ponto crítico": `Uri.TryCreate` com `UriKind.Absolute` sozinho aceita `javascript:alert(1)` como URI absoluta válida. O código já implementa a allowlist corretamente (`!EsquemasPermitidos.Contains(uri.Scheme)` no mesmo `if` do `TryCreate`), mas não há nenhum marcador textual de que remover essa condição reabre a falha mais séria do sistema — ao contrário do padrão já estabelecido em T-08 (comentário de uma linha apontando a ADR-004 no `permanent: false`).
- **Sugestão de correção:** Considerar um comentário de uma linha antes do `if`, referenciando ADR-005, para que uma futura simplificação não remova a allowlist por parecer redundante com o `TryCreate`.

#### R-02 — Commit ainda não criado para T-04

- **Eixo:** 2. Rastreabilidade
- **Referência cruzada:** —
- **Evidência:** `git status` mostra os três arquivos da tarefa como não rastreados/não commitados.
- **Descrição:** A convenção do plano (§2) é um commit por tarefa, com o ID `T-XX` na mensagem, e a tabela de histórico (§11) referencia o hash do commit. Isso ainda não aconteceu para T-04.
- **Sugestão de correção:** Commitar com mensagem referenciando `T-04` e preencher o hash na tabela de histórico de execução do plano.

## Cobertura por RN (Implementa)

### RN-01 — URI absoluta com esquema `http`/`https`, allowlist

- **Como foi implementada:** `Uri.TryCreate(urlSemEspacos, UriKind.Absolute, out var uri)` combinado com `EsquemasPermitidos.Contains(uri.Scheme)` no mesmo `if`, garantindo que tanto entradas sem esquema quanto esquemas fora da allowlist caiam na mesma mensagem de rejeição.
- **Evidência:** `src/Encurtador.Web/Servicos/ValidadorDeUrl.cs:18-21`
- **Status:** ✅ Implementada corretamente — confirmado pelas 7 entradas de `CA_02` rodando individualmente (`google.com`, `www.exemplo.com.br/pagina`, `javascript:alert(1)`, `data:text/html,<h1>oi</h1>`, `file:///etc/passwd`, `ftp://exemplo.com.br/arquivo.zip`, `//exemplo.com.br`), todas rejeitadas com a mensagem literal do PRD §8.

### RN-02 — Limite de 2048 caracteres

- **Como foi implementada:** `if (urlSemEspacos.Length > TamanhoMaximo)`, aplicado sobre a string já aparada, com limite inclusivo (2048 aceita, 2049 rejeita).
- **Evidência:** `src/Encurtador.Web/Servicos/ValidadorDeUrl.cs:23-26`
- **Status:** ✅ Implementada corretamente — `CA_03` (2049 rejeita) e `CA_04` (2048 aceita, inclusive com espaços nas extremidades) verdes.

### RN-04 — Campo obrigatório, trim antes de qualquer validação

- **Como foi implementada:** `(urlInformada ?? string.Empty).Trim()` é a primeira linha do método, antes de qualquer outra checagem; string vazia após trim é rejeitada com a mensagem "Informe uma URL."
- **Evidência:** `src/Encurtador.Web/Servicos/ValidadorDeUrl.cs:9-14`
- **Status:** ✅ Implementada corretamente — `CA_06` (só espaços) e `CA_07` (espaços nas pontas removidos) verdes.

## Verificação da Decisão Arquitetural

### ADR-005 — Validação restritiva de URL por allowlist de esquema

- **Decisão original:** Aceitar só `http`/`https` via allowlist (não blocklist), rejeitar acima de 2048 caracteres, rejeitar destino no próprio host (esta última parte fica para T-05).
- **Implementação:** `EsquemasPermitidos` é um array fechado de dois elementos (`http`, `https`), verificado por `Contains` — é allowlist, não blocklist. Limite de 2048 aplicado como decidido.
- **Conformidade:** ✅ A parte da ADR-005 no escopo de T-04 (esquema + tamanho) está implementada como determinado. O bloqueio de host (terceira parte da ADR) é escopo de T-05, corretamente não antecipado aqui.

## Cobertura por RN (Implementa)

### RN-10 — Acesso a código existente responde HTTP 302 com `Location` apontando para o destino, nunca 301

- **Como foi implementada:** `Results.Redirect(link.UrlDestino, permanent: false)` — o parâmetro `permanent: false` é a decisão inteira, com comentário de uma linha apontando ADR-004.
- **Evidência:** `src/Encurtador.Web/Program.cs:35-42`
- **Status:** ✅ Implementada corretamente — confirmada por `CA_12_CodigoExistente_RetornaTrezentosEDois`, que assere `HttpStatusCode.Redirect` (302 exato, não um helper genérico de redirect).

### RN-11 — Acesso a código inexistente responde HTTP 404, sem redirect para a home

- **Como foi implementada:** `Results.NotFound()` no ramo `else` do `SingleOrDefaultAsync`.
- **Evidência:** `src/Encurtador.Web/Program.cs:35-42`
- **Status:** ✅ Implementada corretamente — `CA_13_CodigoInexistente_RetornaQuatrocentosEQuatro` confirma 404 e ausência de header `Location`.

### RN-12 — Código é case-sensitive

- **Como foi implementada:** comparação por igualdade exata (`l.Codigo == codigo`) sobre coluna sem `COLLATE NOCASE` (confirmado em T-02, ponto de validação humana já fechado). Nenhuma migration nova foi necessária.
- **Evidência:** `src/Encurtador.Web/Program.cs:37`; `src/Encurtador.Web/Dados/EncurtadorDbContext.cs:13-15`
- **Status:** ✅ Implementada corretamente — `CA_14_CodigoComCaixaDiferente_NaoResolve` prova que `/ab3xk9p` não resolve um link gravado como `aB3xK9p`.

### RN-13 — Resolução não altera nenhum dado do registro

- **Como foi implementada:** o endpoint só faz leitura (`SingleOrDefaultAsync`); nenhum `SaveChanges` no caminho de resolução.
- **Evidência:** `src/Encurtador.Web/Program.cs:35-42`
- **Status:** ✅ Implementada corretamente — `CA_15_ResolucaoNaoAlteraORegistro` acessa o link três vezes e reconfirma `UrlDestino` e contagem de registros (1) inalterados.

## Verificação da Decisão Arquitetural

### ADR-004 — Redirect com HTTP 302, nunca 301

- **Decisão original:** o endpoint de redirect responde 302 Found, nunca 301, para manter toda visita passando pelo servidor (protege a demo de cache persistente de navegador).
- **Implementação:** `Results.Redirect(link.UrlDestino, permanent: false)`, com comentário de uma linha apontando a ADR diretamente no parâmetro.
- **Conformidade:** ✅

### ADR-001 — Aplicação única em Razor Pages, com o redirect fora do roteamento de páginas

- **Decisão original:** o redirect é um endpoint Minimal API (`app.MapGet("/{code}", ...)`), registrado após o mapeamento das Razor Pages.
- **Implementação:** `app.MapGet("/{codigo}", ...)` registrado depois de `app.MapRazorPages().WithStaticAssets()` em `Program.cs`.
- **Conformidade:** ✅ — smoke test manual confirmou que `/` (200) e `/css/site.css` (200) continuam servindo normalmente, e que um código inexistente devolve 404 em vez de competir com essas rotas.
